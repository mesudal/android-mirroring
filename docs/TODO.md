# 남은 작업

이 문서는 현재 구현되지 않았거나 추가 결정이 필요한 항목만 기록한다.

## 1. 클립보드 동기화 실기기 확인

미러링 중 PC와 Android 사이에 **텍스트 클립보드**를 자동 동기화한다. PC 클립보드는 약 0.5초 간격으로 변경 여부를 확인하고, Android에서 받은 텍스트는 PC 클립보드에 반영한다.

기본 구현은 완료됐다. Android 버전·제조사별 클립보드 알림 동작을 실기기에서 확인하고, 클립보드가 비어 있는 경우와 긴 텍스트도 점검할 것. 이미지·파일 클립보드는 범위 밖이다.

## 2. UHID 키보드 폴백 정리 여부 결정

키보드는 UHID를 기본으로 쓰며, `/dev/uhid`를 사용할 수 없는 기기에서는 예전 클립보드 입력 방식으로 자동 전환한다.

팀에서 지원해야 할 모든 Android 기기가 UHID를 지원한다고 확인되면 폴백을 제거할 수 있다. 결정 전에는 기존 폴백과 `syncText()` 로직을 유지한다.

## 3. APK 설치 진행 목록

APK 설치 UI는 미러링 탭으로 이동했다. 설치 진행 목록(`installQueue`)은 현재 화면에서 확인할 수 없고 완료·실패 토스트만 표시한다. 여러 APK를 설치할 때 진행 상황을 볼 수 있도록 목록을 노출할지 검토한다.

## 4. 사용하지 않는 화면과 스타일 정리

`page-install` 등 탭에서 접근하지 않는 화면 마크업과 옛 레이아웃용 CSS가 일부 남아 있다. 화면 접근 경로와 참조 여부를 확인한 뒤 제거한다.

## 5. QA 자동화 기능 이어서 구현

QA 대상 앱 목록(`src/qa-apps.js`, 제로톡 3타입)과 기기 화면 왼쪽 메뉴의 앱·타입 선택, QA 탭에서 역할별 기기·앱 타입 선택, 현재 UIAutomator 접근성 요소 조회와 선택 요소 탭까지 구현했다. 사양서의 전체 체크리스트 원본은 아직 없어 실제 테스트 시나리오를 임의로 만들지 않는다.

다음 단계에서 시나리오 목록·실행기, 계정 안전 저장, 다중 기기 동작, 실행 증거·결과 내보내기와 Jira 초안 연동을 구현한다. 실제 체크리스트 시나리오는 원본 시트나 내보내기 파일을 받은 뒤 추가한다.

드라이버(`src/qa-driver.js`)에는 요소 대기, 길게 누르기, 스와이프, 입력, 키, 앱 실행·종료, 기기 상태 명령까지 들어 있고 화면에서는 조회·좌표 탭·글자로 누르기만 쓴다. 아래는 아직 확인하지 못했다.

- 드라이버의 네트워크·권한·오버레이·배터리 최적화·위치 명령의 실기기 동작 (Android 10 / 13 양쪽)
- 로그인 이후 화면(메인, 드로우메뉴, 설정), 토스트, 상주 알림의 마이크 버튼, 플로팅 버튼이 화면 덤프에 잡히는지
- 제로톡은 `resource-id` 가 비어 있다. 글자 없는 버튼(PTT, 톱니, ⋮)을 앱 쪽 접근성 라벨로 풀지 좌표 방식으로 갈지 결정이 필요하다

## 6. 업데이트(버전 간) 테스트

예: 제로톡 55 → 56 업데이트 후 데이터 누락·기능 이상 확인. 아직 구현하지 않았다. 계획:

- **APK 두 개를 입력으로 받는다** (이전 버전·새 버전). 스토어 업데이트는 자동화할 수 없으므로 APK 파일이 있어야 한다.
- 흐름: 이전 버전 설치(필요하면 데이터 삭제 후) → "준비" 시나리오로 데이터를 만든다(로그인, 채널 입장, 설정 변경, 메시지·히스토리) → **스냅샷**(주요 화면의 글자 목록·설정 값·채널 목록, 스크린샷) → `adb install -r` 로 새 버전을 덮어 설치(데이터 유지) → 같은 화면 **스냅샷**을 다시 떠서 비교 → "확인" 시나리오(로그인 유지, 송수신 등)를 돌린다.
- 결과: 스냅샷 차이(사라진·바뀐 항목)와 확인 시나리오 결과를 한 보고서로. 차이는 사람이 판정한다(의도된 변경일 수 있다).
- 제약: 다운그레이드는 데이터를 지워야 해서(`install -r -d` 는 디버그 빌드만 가능) 같은 기기에서 반복하려면 매번 이전 버전으로 새로 설치해야 한다. 앱 내부 저장소(SharedPreferences·DB)는 디버그 빌드가 아니면 adb 로 읽을 수 없어 화면에 보이는 정보로 비교한다.
- 시나리오에 `phase: "before" | "after"` 를 두고, 업데이트 실행은 `{ appId, variantId, fromApk, toApk, before: [...], after: [...] }` 로 묶는다. 체크리스트 원본과 테스트 계정이 있어야 시작할 수 있다.
